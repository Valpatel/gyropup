# Output-adapter ownership

Issue #64, under mechanical integration #61, corrects the current full-robot presentation's four output adapters. `cad/fivebar.py:assembly` places each adapter in its upper-link frame, and `screw_groups` puts its output screws in that same frame. The committed interim body rig instead classifies adapters as fixed body meshes. The renderer previously followed that classification even during current live play.

The archived rig is a recorded physics snapshot. Its meshes, mass and trajectory provenance must remain available unchanged. A current presentation correction must record its source hashes and datums separately and must not imply that the later body, hardware fit, mass, FEA or robot dynamics were regenerated.

`exports/sim/v2/leg-attachments/` contains a joint-local adapter and nine individually named output screws. The shared robot builder instantiates these on each upper link: four adapters and 36 screws. Motor housings remain fixed. Recorded mode hides those attachments and restores the original four fixed adapter meshes, with their original transforms and rig files unchanged. Failed or stale archived loads cannot change the current attachment selection. New `sim/robot_v2.py` exports put the same parts directly in `links.upper` and do not emit fixed-body adapters.

The adapter is a rigid translation of project geometry from commit `31908a86a782c440e47beb0f502e3ef0fd944aa2`, pinned by SHA-256. Its former body-frame motor-axis x is 75 mm; the upper-link datum y is 82.3 mm, independently checked from the adapter face y 85.3 minus its 3 mm CAD spigot. `tools/export-leg-attachments.py` preserves its vertices and subtracts that origin. Current screw seats are checked against the same 24.6 mm adapter face before export. The manifest records source hashes, generation revision and the coordinate migration.

The screws reuse `fivebar.upper_output_screws()`, extracted without dimensional change from the existing assembly logic. Each is a project-authored cylindrical envelope for catalogue `screw_m5x25`, McMaster 91290A252: 25 mm shank, 8.5 mm diameter × 5 mm head, nine centres on a 36 mm bolt circle. No supplier STEP or derived supplier mesh is published. Hex sockets and threads are omitted. The catalogue's vendor STEP path is currently missing despite its `available:true` flag, so this work does not claim a vendor-model fit or tool-access check.

## Reproduction and independent validation

Run the bounded export on an isolated CAD runner with `python tools/export-leg-attachments.py`. Fetch the pinned historical commit first if the checkout is shallow. It does not run the full body build, simulations or FEA. Preserve archived rig files. The committed attachment export was generated from source `90837db` on the isolated CAD compute environment with cad-agent v0.4.0.

`tools/build-leg-motion-reference.py` creates a reviewed reference using cad-agent's `required_poses`. It is not run automatically by the browser regression. Axes and ownership come from `fivebar.assembly/link_frames`; fixed motor STL cylinders independently establish x ±75, z 0 shafts. The reference linkage is 150/150/250 mm at a 300 mm nominal leg height. The adapter's reference vertices come from the original body mesh, rather than the new attachment export's asserted translation. Screw centres, radius, seat and length have separate stock-dimension checks. At least four noncoplanar actual STL vertices are selected for each component; mirrored winding indices are accounted for explicitly.

`SITE_URL=<built preview> npm run test:legs` runs four static/export checks and the actual shared renderer on sim, landing and talk routes. It checks 44 components across 17 required joint poses plus one simultaneous pose, 60 live control frames, and an explosion restore. World vertices are converted from page metres to CAD millimetres after removing only the robot free-body placement. Tolerance is 0.02 mm, chosen for float STL export precision. It also checks delivered mesh hashes, all 40 attachment instances, archived transforms/selection races, and missing-part fallback. Wrong-parent and wrong-pivot controls preserve the correct home placements before moving; wrong axis, rotating stationary motor and unit errors must also fail.

Select WebKit with `PLAYWRIGHT_BROWSER=webkit`. Evidence is written under `TEST_OUTPUT` (default `/tmp/gyropup-leg-attachment-motion`). Validate each saved capture independently with `cad-agent motion-trace contract.json chromium-trace.json --tolerance-mm .02 --output report.json`. CI runs the regression in the existing mechanism suite.

The first complete Chromium capture passed all 79 samples; maximum landmark error was 0.0000055 mm. The wrong-parent control moved an adapter 16.435 mm; the restored correct scene returned below tolerance. Current turret and hero compatibility suites also passed. Final release/engine evidence belongs to the PR and CI receipts for the reviewed head.

This validates sampled rendered ownership and the specified attachment inventory. Independent joint probes are not closed-loop physical poses. It does not establish full model completeness, continuous clearance, socket access, threads, physical fit, manufacture, loads, dynamic balance, or hardware safety. Hardware dimensions and the historical mass/physics results remain unchanged.
