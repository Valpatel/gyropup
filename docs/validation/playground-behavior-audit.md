## Open findings at the audit handoff

- Focused ARM plus Space did not arm (`arm=[]`); focused FIRE plus Enter while already armed did not trigger (`trigger=false`, `queue=0`). These hold buttons use pointer handlers, while global keyboard handling correctly defers to focused buttons. Add button-level keydown/keyup and release-on-blur behavior, then cover it in the regression suite.
- The new turret interaction regression's exact slider accessible-name selector timed out: its enclosing label includes the current value and unit. The AUTO chip also has an explicit descriptive `aria-label`, so its visible text is not its accessible name. The rate starts at its maximum 3, so initialize it to 1 before expecting ArrowRight to produce 2. After a journey, wait for arc visibility to update rather than accepting already-populated old prediction points. After changing viewport, allow responsive layout to settle and open the real phone drawer before checking its children. Correct test setup and locators before claiming that suite passed. An independent scratch copy with corrected setup passed native keyboard ownership, real journey pause, reload spam/fire/journey gates, hardware exit/reentry, preserved scene/conversation, reduced motion and five reachable phone layouts. A separate focused probe passed the three AUTO centering layouts. The unchanged repository suite still needs these setup corrections and a full rerun.

## Evidence and method

The independent broad probe `/tmp/gyropup-playground-audit.mjs` checks deliberate control groups, state changes and scene identity rather than clicking arbitrary buttons. The portal probe `/tmp/gyropup-portal-audit.mjs` and receipt `/tmp/gyropup-portal-audit.json` cover the landing page, progress, build, design notebook, FEA and character demo. Built-site portal receipts are `/tmp/gyropup-portal-chromium/report.json` and `/tmp/gyropup-portal-webkit/report.json`, both with no page errors or missing required resources. Scratch paths describe this session's evidence and are not durable repository dependencies.

The first broad probe used fixed wall-clock delays. On the shared software-rendered browser, those did not imply sufficient simulated time: a 700 ms wait advanced the scene by only about 0.1 simulated seconds. Such timeouts are not recorded as product failures. Wait for a state predicate or measure simulation time. Likewise, do not serialize a selected Three.js object graph in an assertion: capture small scalar properties such as its name instead.

During ongoing changes, one preview build imported `designer/robot_actions.js` before that file was included in the static output. The module returned HTTP404 and the simulator did not initialize. The owner staged the new files and rebuilt, resolving the missing import. Final verification must use a coherent build and reject missing module requests.

A browser test should check console errors, failed required resources and `document.body.dataset.stageError`; catching a frame callback exception keeps the page alive but does not make that callback healthy.

## Experience judgment and limits

The bright curved guide and visible jar pour make the main battle loop easier to understand. The large ARM, RELOAD and FIRE controls communicate the central actions well. Inspection modes and the journey are useful demonstrations of the machine, while the portal exposes the project's progress and engineering evidence. Those are visual and interaction judgments, not proof that children will find the game fun.

A human play session should still assess aiming satisfaction, touch ergonomics while holding ARM and firing, pacing, audio balance, emotional appeal and whether the first minute explains itself. The automated checks do not establish hardware reliability, physical projectile behavior, collision safety, real microphone/voice quality, network-filter reputation, every possible phone/browser combination or accessibility conformance. Representative phone layouts are tested rather than claiming every phone resolution exists as a finite test set.
