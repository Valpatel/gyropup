# Downloadable engineering files still need a usable portal view

On 2026-10-29, the reviewed PAN protection candidate's native KiCad files and Markdown notes were copied into the static bundle, but document discovery included only `docs/` and `research/`. Its three `hardware/` notes therefore had no rendered/indexed human pages. Commit `b61b064` includes tracked hardware Markdown in the existing notebook while preserving the AGENTS/CLAUDE/handoff exclusions and original downloads. Independent exact-commit review checked all 13 local article links, five Markdown tests and the unchanged published circuit receipt.

The subsequent real browser check found a separate usability gap: the standalone schematic SVG retained its A3 width. Both 320 px and 1440 px Chrome viewports reported a 1587 px document width, initially cropping the drawing. The circuit README now embeds a responsive preview using the existing document image style and provides an explicit original-SVG download. The original vector and native schematic are unchanged; the source-bound receipt was regenerated for the README edit. Users can zoom the page for detail and obtain the full-size source.

Corrective rule: verify discovery, rendered notes, source-relative links, visible media and original downloads independently. Copying an artifact proves none of the other steps. Preserve file/source integrity while providing a usable consumer view; do not rewrite native CAD or SVG geometry to fit a website. Scope remains an unselected circuit candidate, not fabrication, electrical or physical qualification.

A later specimen-page screenshot at320px exposed the same broad class inside a nested table: document scrollWidth passed while the primary Preview3D action was beyond the table's visible right edge. The two specimens now use stacked entries with optional mesh downloads in a disclosure. `tools/test-build-portal.mjs` checks every specimen's real action rectangle and centre-point hit target at320/390/1440px, and deliberately translates the action offscreen to confirm rejection. Contained overflow is acceptable for a large comparison table only when its intended navigation is tested; it is unnecessary friction for two primary inspection links.
