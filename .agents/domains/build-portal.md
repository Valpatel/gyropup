# Parts retain their identity when their table changes

Gyropup's Build and Progress checklists use the shared cad-agent table/tracker modules unchanged. Update those modules from an identified toolkit commit, and put product wiring in `designer/portal-parts.js`. Report toolkit defects upstream instead of patching a divergent product copy.

Stable status keys describe catalog parts, manufactured parts or scoped print parts. Sorting, filtering, seller grouping and workstream inclusion must never change those keys. Dispose old table enhancers before replacing report nodes; otherwise old tracker subscriptions survive and toolbars/status columns can duplicate. Use raw source numeric values in `data-sort-value`, with empty values for unknowns. Do not parse arbitrary formatted labels or move fixed totals through the sort.

On narrow screens, tracked tables retain a compact sticky Part column so horizontally scrolled status controls still identify their row. The scroll wrapper must own overflow; `overflow:hidden` on the table itself can trap the sticky cell and move it offscreen. Test the fully scrolled table at 320px with actual hit testing: identity stays visible, both status labels remain at least 44px and neither is obscured by the sticky column. Keep semantic headers wide enough to wrap between words. Picture-only columns do not have meaningful sort keys.

The published-model inventory is generated from tracked files inside the existing public roots. It intentionally differs from all tracked CAD: the 27 Upkie reference STLs in `rl/vendor/` are not published. Keep original download addresses and add preview affordances around the web UI; do not rewrite CAD or report data to viewer URLs. Scoped media keys and source links follow [part image identity](part-images.md).

`tools/test-build-portal.mjs` exercises actual native controls, cross-page persistence, invalid imports and denied storage, numeric/text sorting and all published original/preview mappings. `tools/test-markdown.mjs` protects the validated published-data snapshot. Parser corpus validation remains separate from link coverage. See `docs/validation/build-portal.md` for the integration contract and limits.

For small preparation pages, keep primary model-inspection actions in the initial horizontal viewport. Test their actual rectangles and hit targets after scrolling into view: page-width checks do not detect clipped actions inside a scroll wrapper. Prefer stacked entries for a few items; reserve horizontal tables for comparisons that need them. The specimen case in `tools/test-build-portal.mjs` includes an actual offscreen-action negative.

Do not call `scrollIntoView` before an initial-horizontal-visibility assertion: it can scroll nested ancestors to hide the defect. Scroll vertically only, check clipping-ancestor bounds and unchanged horizontal offsets, and test a real nested overflow corruption.

Clipping fixtures around decorated model links must preserve the original-download/preview sibling pair. Wrap their common paragraph; moving only the preview legitimately triggers the live decorator to create a replacement and makes the test exercise a different behavior.


Desktop assembly instructions (>760px, excluding short coarse-pointer phone landscape up to 1000px) stay at the right edge when Tools is closed and immediately to its left when open. Expanding instructions changes reading height, preserving the independent Parts/Tools controls. Native fullscreen and denied-fullscreen expansion use the same docking CSS and actual-box camera insets. Side-panel widths share the remaining workspace budget with the instruction card and a 320px model lane where desktop width allows it. `npm run test:instruction-docking` owns and closes its temporary listener and exercises all panel states, real hit targets, fullscreen completion, resize and narrow touch sheets in Chromium/WebKit. Short ordinary windows remain scrolling documents; fullscreen must keep controls in its viewport.

Short coarse-pointer landscape at 600–1000px wide and <=500px high uses a single tabbed pane at right, with its real width reserved in the camera inset. Its selected-part popup fills that same pane below the visible tabs. Portrait retains its bottom sheet, and fine-pointer desktop retains independent panels. Expand changes the landscape pane width; actual projected model dimensions and the remaining viewing lane are acceptance criteria alongside unoccluded vertices and 44px pointer targets.

Desktop Selected part details use the existing Parts dock, including on direct canvas selection; the camera reserves that dock before the inspector paints. Preserve all fields and standard actions. Regressions must retain an actual isolated-part centroid click with the inspector open, rather than search for another point that avoids an overlapping popup.

Tools Reset and Selected part Isolate/Print occupy fixed pane footers while their variable controls/details scroll. Native focus, pointer and keyboard semantics remain unchanged. Regressions observe trusted pointerdown/up/click at a stable rectangle and the resulting model/section state, plus real touch and Tab navigation into the action buttons.

Playback UI refreshes compare native properties/attributes/text before writing. The adapter pauses from host-capture pointerdown; redundant native-control rewrites there can move scrolling targets before their click. Contextual Loop/Rotate/Flip remain in their existing groups. Verify idle, already-paused and genuine playing→paused actions with stable native targets, unchanged section state and stopped player time.
