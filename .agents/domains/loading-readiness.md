# Loading readiness and report availability

Browser loading is an operation state, not a page animation. Keep a visible status until the requested data has passed HTTP, format and geometry validation and the first usable frame or report exists. Use `designer/kit/loading.js`; pass the token returned by `begin()` to every asynchronous completion. Callers must also guard their own DOM/scene mutations against stale requests.

`designer/kit/portal-data.js` distinguishes an explicitly optional HTTP404 from transport errors, other HTTP status codes and malformed data. An unpublished optional export can be labeled unavailable. A failed required catalog, report or mesh cannot become an empty list, a zero total or a partial assembly labeled ready. Build excludes incomplete workstreams and labels the remainder a published-data subtotal. Progress uses independent section states so one report cannot block unrelated reports.

A required STL must have a plausible STL payload and finite, nonempty triangles before the assembly becomes ready. The byte guard must match the vendored parser’s exact binary/ASCII classifier; do not trim text or accept uppercase prefixes that the parser treats as a binary face count. Do not create a partial scene while required parts are still loading. Retrying the character model keeps its stage canvas; do not remount conversation controls on an already mounted robot. Download/parse phases are labels, not invented percentages.

Agent Markdown uses the same portal renderer and data reader against the published bundle only. UI status is adapted for static rendering; an error state rejects a partial snapshot. Optional unpublished sections remain explicit. Never add a hidden checkout-data fallback to make the static build pass.

`tools/test-loading-portal.mjs` injects held requests, HTTP503, offline failures, HTML returned as JSON/STL, empty geometry, malformed structural surfaces and stale progress completions. It checks retry behavior, unrelated report identity, first rendered frames, phone controls and reduced motion. `tools/test-markdown.mjs` verifies static failure isolation and published-data provenance. Existing model and portal-viewer suites remain necessary: loading tests do not establish mechanism correctness, scientific validity or good camera framing.

A retry action must invalidate failed metadata as well as failed geometry promises. A cached malformed recording summary can otherwise make every visible retry fail without another network request. Keep the existing live scene and conversation while retrying required turret files or selecting a recording; a newer live action must invalidate the pending recording selection.

Measure the actual stacking result on phones. A status inside the HUD's z-index 4 stacking context cannot escape a body-level speech bubble at z-index 7 merely by giving the status z-index 12. Simulator retry feedback is anchored to the stage from a body-level host, bounded above the action bar, without changing camera insets. `tools/test-loading-sim.mjs` checks native retry refetches, scene/conversation retention, delayed-recording cancellation and actual visible text/control hit testing at 320×568 and 844×390.

Entry-graph failure must not depend on importing the status helper. Portal entry HTML statically links the loading CSS and catches dynamic-import failure with a visible native reload action. This fallback applies only before a usable scene exists. Keep data/model retry inside the mounted app so normal recovery does not reset conversation state. The browser harness holds and fails each distinct entry graph, including the loading-helper module itself, and requires a real refetch after reload.

Required model data includes every kinematic dimension, reference angle and mount vector consumed by the builder, not only the presence of a `fivebar` or `turret` object. Reject missing/non-finite dimensions before requesting meshes. `test-loading-portal` mutates eight such fields, requires an error without mesh requests or conversation mounting, then recovers on the same canvas and checks every actual world matrix is finite.

First-load failure fixtures must be installed before any successful visit populates that model's cache. Assert the uncached precondition, count intercepted attempts, require a real recovery fetch, then separately assert the recovered object's identity and no refetch on cached return. `tests/site/controls/test-sim-transitions.mjs` applies this to the bench while retaining the current robot, scene and conversation. A late route on an already cached object does not test failure handling.

On a core readiness timeout, retain the original predicate/deadline/failure first. The empty-space harness then records one bounded, read-only current scene/startup/error/request snapshot and an exclusive failure report. Keep normal CI's real environment, redact endpoints/queries/private data, and preserve diagnostic read/write failures as secondary evidence. A timeout with no scene/request capture does not identify a model, legacy-policy or timing cause; do not change the success criterion from a different-profile success.

Apply diagnostic redaction to actual URL/path classes, not only HTTP(S) and home directories. Remove queries/fragments from allowed about labels and owned URLs; reject external/opaque/encoded URL payloads and bare filesystem paths, including temporary and Windows forms. Exercise the actual error/console/state serialization with adversarial synthetic inputs alongside positive public-path/replay/numeric observations. Passing a few redaction examples does not establish full format coverage or diagnose a readiness timeout.
