# Progress publication

Maintain `docs/progress.json` alongside meaningful engineering checkpoints and website releases. Use dated entries linked to reviewable evidence. State whether work is live, integrated only on an engineering branch, still under review, or physically measured. Do not auto-stamp a report as current merely because the site rebuilt. Old mass, strength and stock notes remain historical rather than current approval.

Keep three recent entries, a concise current focus and the source-bound static deformation study visible. Long history is grouped by date in native `details`; detailed tables, galleries and procurement also use disclosures. Every existing anchor must reveal all enclosing disclosures, including a repeated click on the current hash. Retrying the progress data preserves expanded history dates. Collapsing logs must not recreate the media player.

The agent Markdown route includes all collapsed content. Check every entry title, original report/download links and the static-analysis meaning. The default featured case is hip-frame E1, with its failed safety factor and historical load baseline; other stills are not promised animations. See [structural media](structural-media.md) for scientific provenance and playback checks.

Run `npm run test:progress`, `test:study-media`, `test:build-portal`, `test:loading-portal` and `test:markdown` for relevant changes. Use Chrome/CI Chromium and WebKit for disclosure, media and phone checks; inspect actual phone/desktop screenshots. Shared loading-status wrappers must not leave empty grid cells.
